## Phase 3: the substrate (in `packages/platform/synergy`, proven by mock note and task modules)

**3a. Store and rules**

- Entity index, version log, relationships (single and list), relation vocabulary, tags with key:value, aliases and deprecation.
- Every backend foundation: RLS, constraints, provenance, outbox, indexes, concurrency.
- Rules: staleness snapshot, edited and changed dot derivation, delete blocked while referenced (references only), erasure override, no reference cycles, supersede marks the old entity, deleting a target block deletes the associations into it (`to_anchor` stored, editor use comes later), restore checks.
- Repository as the only access path. Guarded API with the stable error codes and idempotency keys.

**3b. Render and find**

- Resolver registry and renderer registry, both batched.
- The Rich Live Link component, MVP-complete in all four display types and every state, in plain text (no icons, no pills, no hover), built on the frontend foundations.
- Note and task renderers. Render cache.
- A playground page behind the `sandbox` entitlement: mock notes and tasks with their fields, tags, outgoing links, backlinks and all four display types, driven through the public API. Plain, unstyled HTML: forms, textareas, lists, buttons and the raw API response. No rich-text editor, modals, hovers or styling. Just enough to test the responses and check Synergy is ready for what the PRD commits to.
- Backlinks API ("who references me").
- Search over title and metadata (type, status, tags, provider), with filters and cursors.
- Mock **note** and **task** modules in `packages/ops`, behind a `sandbox` entitlement, prove the model across a module boundary. They retire with the rest of ops; their renderers stay as Synergy test fixtures.
- Fix the existing RLS policies (sidekick migrations 0002 and 0007) to compare uuids directly.

**Exit criteria.** Integration tests through the public API only prove that:

- a link can carry a label and a type
- a version bump with a change note shows the red dot
- deprecate and supersede work
- deleting a referenced target is blocked
- reference cycles are rejected
- `key:value` tags work
- search finds entities by title and metadata
- disabling a module makes its links locked
- another user's entities never leak

## Rest of the MVP (lands with the modules that need it)

- **Rule for every module:** each entity type that can appear as a Rich Live Link (datum, narrative, plan, chat session, and so on) ships its own renderer, registered for any consumer that needs to show that type.

- **Phase 4, Taxila:** datums and narratives as the first real tenant. Labeled list links, `derived-from` between narratives and datums, supersede confirmation flow. Source anchors (selected text becomes a minimal link) and block-level target anchors in Taxila's editor.
- **Phase 5, Zinsser:** word and sentence target anchors, using the algorithm system design chooses.
- **Phase 6, AI layer:** AI tag suggestions waiting for approval (with the auto-accept setting), AI-generated narratives that link their sources, and AI advice on whether a change deserves a version bump (the author still decides).
- **Phase 7, War Room:** plans referencing datums and jobs, which proves cross-module links and locked states with a real second module.
- **Phase 9, API keys:** bots and agents use the same API. Scopes only narrow access.

## Post-MVP candidates

None of these is committed. Review and prioritise them once the MVP ships.

- Styling: type icons, status pills, hover and click details on links.
- Bulk link and tag endpoints.
- Readers reporting broken or obsolete sources. Notifications to authors and referencers (via the outbox).
- Diffs and "as linked" views of a changed target.
- Body-text search, and search providers if system design picks them.
- User-defined relation types. Linking to a link.
- References between users, with redaction and the npm-unpublish delete rule.
- Judging intent with AI. Drift detection between near-duplicates.
- External renderers (Slack and similar). Publishing links on a public Taxila post.
- Third-party consumers of Rich Live Links: Slack unfurls, Notion embeds, an oEmbed endpoint. The component is built host-agnostic in the MVP so these need no rewrite.
- A "payment overdue" message for locked links. A closure table if cycle checks get slow.
- AI tag-merge suggestions: a periodic scan proposes merges (`ml` into `machine-learning`) and the user approves each one, never automatically. It calls the same merge action, so it needs no data-model change.
- A `reviewed_at` the author sets when they reaffirm an entry is still true without editing it, for freshness prompts ("not reviewed in 6 months").
- Pushing "Page updated" to open pages (server-sent events or Supabase Realtime, fed by the outbox) instead of the MVP's check on focus and every 30 seconds.
- A block-level patch endpoint for bots and agents, so they can change one block without sending back a whole document full of marks they don't understand.
- Rich hover cards for terms and links. The MVP uses the browser's native tooltip for term definitions.
- Term highlighting any feature can invoke: scan text and suggest a link on the first use of each known term or alias, approved by the user.

## For system design

> Settled on 2026-10-30; see [[03-system-design/functional-design/04-synergy/00-overview|Synergy]] and its decisions. The list is kept as asked.

- How word and sentence anchors survive edits: survey the common algorithms (text-quote selectors, position plus context, CRDT-relative positions, fuzzy re-matching) and how other tools handle it. The bar to beat: operation-based anchors, moved through every editor step (ProseMirror/Tiptap or Lexical, with CRDT relative positions such as Yjs for offline and concurrent edits), with text-quote re-matching and diffing as the fallback for content that arrives whole from bots or the API. Block ids stay stable on a move; a merge counts as a delete.
- The referenced-passage check on save must cost the size of the change, not the document, so autosave can follow the MVP closely.
- How the cycle check scales: recursive query, depth cap or closure table. Measure first.
- Where Lexicon term highlighting lives so every feature can call it (terms themselves belong to Taxila).
- Whether search uses a provider model like renderers.
- How to mock and test a module in isolation: Storybook or something better (Ladle, Vitest browser mode, Playwright component tests, MSW).
- Where the renderer and resolver contract lives so Synergy never imports the feature registry (see [[02-prd/03-features/01-synergy/research/05-resolver-contract-home|research 05]]).
