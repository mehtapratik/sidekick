An **entity** is anything linkable in any module: a Taxila datum or narrative, a War Room plan, an Alter Ego chat session, a scheduled job. A **datum** is Taxila's compact entry, one fact per entry; a narrative can be built from datums, and datums can be split out of a narrative.

## The entity index

`packages/core` keeps one thin row per entity, written when the entity is created and updated with it. The index answers every question that crosses modules (staleness, backlinks, search, delete blocks) without asking each module. Anything richer, like a card's excerpt or a live preview, comes from the owning module's renderer at render time.

**System fields** always exist and the user never fills them in or sees them as metadata:

| Field            | Meaning                                                                               |
| ---------------- | ------------------------------------------------------------------------------------- |
| `id`             | Client-generated UUID                                                                 |
| `owner`          | The user who owns the entity                                                          |
| `module`, `type` | The owning module (its feature key) and the entity type                               |
| `status`         | `active` (default), `deprecated`, `superseded` or `deleted`                           |
| `version`        | Goes up only when the author flags a change that might invalidate references          |
| `revision`       | Goes up on every other save                                                           |
| `display_name`   | The title, or a short name the module derives from the content when there is no title |
| timestamps       | Created, updated, deleted                                                             |

**User metadata** is all optional: title, tags, change notes, and anything a module adds. The user, or the bot or agent that produced the entity, picks what matters. Many datums are a sentence or two, so metadata must never be required.

## Versions and revisions

- The author decides when a change is a new **version**. An AI assistant may advise on its impact on dependents; the author has the final say.
- Every other save is a new **revision**: new content, grammar, formatting.
- Only author content counts: title, body and blurb. Metadata, tags and status never bump either counter.
- A version bump may carry an optional one-line **change note**, stored in a version log in `packages/core`.
- Versions are plain integers. Keeping full content snapshots per version, which diffs need, is each module's job.

## Lifecycle

- **Deprecated:** still readable, marked as out of date.
- **Superseded:** replaced by another entity through a `supersedes` relationship.
- **Deleted:** soft-deleted. The index row stays as a tombstone so a link can still name what it pointed at. An entity with incoming references can't be deleted (see [[04.prd.features.synergy.keeping-links-true|Keeping links true]]).
- Status changes never bump the version.

## Watch

Metadata on micronotes can outweigh the note. Observe real use and study how other tools handle properties on small notes before deciding whether metadata should scale with the size of the entry.
