A Rich Live Link is how a relationship appears inside any document, in any module, and in apps outside Sidekick. Nothing is ever copied; the link shows the target where it lives. It is the only UI Synergy ships to real users. Phase 3 also has a playground page behind the `sandbox` entitlement, for the owner to see relationships, tags and links on mock entities.

## Display types

The author picks the display type per link. Readers can't change it.

| Type                 | Shows                                                                               | When                                |
| -------------------- | ----------------------------------------------------------------------------------- | ----------------------------------- |
| **Inline** (default) | `{title} ({type}) - [{status}]`, then a dot if the target moved                     | Unlabeled links                     |
| **Card**             | Title, excerpt and module fields from the renderer, status, marks, change note      | Unlabeled links                     |
| **Live preview**     | The whole target in place, current content, with the change note if it changed      | Unlabeled links                     |
| **Minimal**          | Only the author's label, with a red superscript dot when the target needs attention | Every labeled or text-anchored link |

- A minimal link carries a browser-default tooltip, `{type} - {status}`, so the label stays clean and the details are a hover away. A term link's tooltip shows the definition instead.
- Previews don't nest. Links inside a live preview render inline.
- A changed target's preview shows current content. "As linked" views and diffs are post-MVP.
- The MVP is plain text: no type icons, no status pills, no hover cards. Styling is added later without touching the contract.

## Who renders what

The component owns the frame: display type, status, marks, and the loading, error, empty, locked, redacted, deleted and "No longer linked" states. A mention in the target reads with the inverse type name. The content comes from a **renderer** that the owning package registers for its entity type. The component calls the renderer and puts the returned React children inside its frame.

- Every module ships a renderer for each entity type that can appear as a link: datum, narrative, plan, chat session and so on.
- Inline and minimal need no renderer call. Everything they show is in the index.
- Card and live preview call the renderer.
- **Open to new types.** Any package adds a linkable type by registering the type, a resolver and a renderer; core and the component never change. Tomorrow that could be a Twitter thread or a news article, linked and associated like any entry. Because the component doesn't know how to render any type, a renderer can also come from outside Sidekick (a Slack thread, say). Storing external links stays Taxila's job.

## Outside Sidekick

Rich Live Links are consumable by third parties. When Notion or Slack shows a Sidekick link, it can show the same card or live preview, with the same states and dots, through the same public API (One Interface). So the component assumes nothing about its host: no app-wide context, the caller's credentials passed in, and output that can also be served as an embed. The MVP builds the component this way; the integrations themselves (Slack unfurls, Notion embeds, oEmbed) are post-MVP candidates.

## Renderer contract

- **Async from day one:** `render(links) => Promise<ReactNode>`. A renderer with everything in hand returns straight away; one that needs data awaits it.
- **Batched:** links on one page are grouped by owning module, and each module gets one call. A plan page with 20 datums, 8 tasks and 2 chat sessions makes 3 calls, not 30.
- **Never called** for deleted, locked or redacted targets.

## Machines

Bots, jobs and agents get the same resolved link as structured data through the same API: relationship, target index fields, state and marks, and render data when asked for. They ignore the display type.

A throwaway prototype of the display types and states is published as a private page, linked from [[02-prd/03-features/01-synergy/tickets/08-rich-live-link-draft|ticket 08]].
