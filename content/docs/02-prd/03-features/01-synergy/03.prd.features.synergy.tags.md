Tags are optional, owned per user, and live in `packages/core` beside the entity index. They can be applied to entities and to relationships.

- **Spelling:** lowercase ASCII letters, digits and dashes, plus one `:` between key and value (`domain:spending`). Input is lowercased automatically; any other character is rejected with a hint, never silently converted.
- **Flat and key:value** tags both work. Keys are free, with autocomplete from keys already in use. Sidekick ships the keys its own modules rely on (`domain`, `situation`, Core Drive's applicability keys).
- **No nesting.** One key, one value.
- **A tag is a record** (id, name, optional description), not an entity: no versions, no lifecycle beyond deprecation.
- **Rename** changes the tag everywhere at once. **Merge** moves every use to another tag and keeps the old name as an alias that suggests the new one. **Deprecate** keeps existing uses and refuses new ones.
- **AI tags** wait as suggestions until the user approves them. A setting lets the user auto-accept.
- Tags never bump an entity's version or revision.
