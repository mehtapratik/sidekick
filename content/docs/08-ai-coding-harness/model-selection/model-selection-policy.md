Select a model by task risk and teaching value, not by habit.

- Use the daily teaching model for routine explanation-led work.
- Escalate to a stronger reasoning model for security, backend, RAG, or other high-consequence lessons.
- Use a fast implementation model for auto-pilot tasks with low teaching value.
- Use a high-stakes architecture reviewer only for decisions that will shape the project for months.
- Brainstorm and draft before implementation, then pressure-test consequential choices with stronger reasoning.

Model names, pricing, and availability change. Treat this policy as the durable contract; keep any current roster in session-specific planning rather than loading it into every coding task.
